## 1. 这是什么项目

毕设项目：在 Luckfox Pico Max（RV1106，1 TOPS NPU，256MB 内存）开发板上，用 C++/RKNN 实现边缘端**行人检测 + 人群聚集分析 + 三级风险预警**。摄像头进、风险等级出，一条复合流水线：

| 环节 | 做法 | 解决什么 |
|---|---|---|
| 检测 | YOLOv5n + INT8 量化，跑板端 NPU | 在 1 TOPS 上实时检出行人 |
| 几何校正 | IPM 逆透视映射（单应矩阵） | 像素脚点 → 地面米制坐标，消除透视畸变 |
| 拓扑分析 | 2.0m 邻接建图 + 图拉普拉斯谱特征（Fiedler 值等） | 区分"人多但分散"与"人数相同但局部聚集"（10 人分散不危险，6 人挤门口危险） |
| 时序决策 | Kalman 多目标平滑 + RiskFSM 有限状态机（滞回 + 确认帧 + DANGER 保持） | 消除检测抖动导致的等级来回跳 |
| 输出 | SAFE / WARNING / DANGER + 画面叠加 + RTSP 推流 | 实时可见的分级预警 |

同一套算法有 **Python 原型（PC 实验）与 C++11 header-only（板端）双实现**，接口刻意对齐，靠黄金数据回归防漂移（见 4.3）。

**口径提醒（写论文/答辩材料前必读）**，依据 `results/rerun/_comparison_summary.json` 的 `_note` 与 `results/rerun/README.md`：

1. 82.5% 是"检出人数 / GT 人数"的**检出率**，不是识别精度（无身份匹配口径）。
2. 增强后 DANGER 帧（11748 vs 2190）与 DANGER 视频数（66 vs 24）**高于**基线——这是 FSM 评分含密度权重 + 谱特征 + DANGER 保持机制带来的更敏感、更稳定，**严禁写成"增强后 DANGER 下降"**。
3. 视频无人工真值，31/111 条全程 SAFE 不能写成"零误报"，只能陈述"未触发告警"。
4. 消融 C 组（+FSM 无谱）与 D 组（完整）的差异即为谱特征独立贡献：切换次数不变（4.3），DANGER 帧 +152（+10.2%）。谱特征已接入生产 FSM 评分（w4=0.1），勿将其写成"未接入"或"无增益"。
5. 7.46 FPS 是板端 profile 口径，6.9 FPS 是客户端拉流口径，两者不要混用。

## 4. 端到端数据流

### 4.1 板端实时链路（C++，`src/luckfox_rtsp_yolov5/src/main.cc`）

```
摄像头 VI（720×480 NV12）
  → 双单遍定点预处理：①NV12→BGR 全帧（画框/VENC）②NV12→RGB letterbox 640×640（直写 RKNN 输入）
  → RKNN YOLOv5 推理 → 解码 → target_classes 过滤（默认 person）
  → 脚点 = 框底边中心 → letterbox 逆映射 → 单应 IPM → 地面米坐标
  → EnhancedDecision::processFrame（默认启用）
      Kalman 多目标平滑 → graph_laplacian 谱特征(n/density/r_gcc/fiedler) → RiskFSM 稳定等级
  → 画框 + 顶部等级色条 → H264 编码 → RTSP :554/live/0
```

旁路配套：`RiskEngine` 经典规则引擎默认关闭（`enable_risk_engine_fallback=false`，仅对照/兜底）；看门狗——VI 连续失败 30 次主动退出交 systemd 重启；每 90 帧打印 PROFILE 分段耗时；阈值启动时从 `config/default_config.json` 加载，失败回退默认值。

### 4.2 PC 实验链路（Python，离线验证与论文证据）

```
dataset/images500（500 图）/ dataset/videos50（111 视频）
  → YOLOv8n 检测 person → 脚点 → IPM 地面米坐标
  ├─ 基线：graph_laplacian 特征 → AND 规则分级（crowd_test.py / rerun_video_baseline.py）
  └─ 增强：谱特征 + KalmanTracker + RiskFSM（crowd_test_enhanced.py）
  → results/rerun/*_timeline.json → regenerate_comparison.py / ablation_study.py / plot_results.py
```

### 4.3 双实现一致性保障（本项目工程化的核心亮点）

```
Python 参考实现 → scripts/generate_golden.py → tests/golden/{graph_laplacian,ema_smoother,risk_fsm}.json
   ├─ Python 侧 test_golden_regression.py（防自身漂移）
   ├─ Python 侧 test_golden_independent.py（numpy 手算独立锚点，防"C++/Python 同时错"）
   └─ C++ 侧 test_golden_regression.cc 读同一批 JSON（防 C++ 漂移）
预处理另有一条链：OpenCV 权威参考 → tests/golden/preprocess/* → C++ test_preprocess（±2 灰度容差）
```

三套规则实现（Python 基线 / 基线脚本 / C++ RiskEngine）历史上出过 OR/AND 口径分歧，现已用 test_baseline_consistency / test_comparison_consistency / test_ablation_consistency 三个一致性测试长期锁定为公平 AND 基线。

```bash
# 测试（CI 同款；改动后必须全绿）
python -m pytest tests/ -q                 # Python 全量
cd src/luckfox_rtsp_yolov5 && make test    # C++ 主机单测（只需 g++）

# 复现实验（项目根目录）
python scripts/crowd_test.py --input dataset/images500 --output results/images500_baseline --device 0

python scripts/ablation_study.py           # 消融 A/B/C/D
python scripts/plot_results.py             # 出图 docs/figures（需 matplotlib）

# 板端
make luckfox LUCKFOX_SDK_ROOT=<SDK路径> CROSS_COMPILE=arm-none-linux-gnueabihf-   # 交叉编译
sudo bash scripts/start_demo.sh           # 一键演示（硬件自检门禁 + RTSP + go2rtc 网页观看）
sudo bash scripts/hardware_selftest.sh    # 开机自检（退出码=失败项数）

bash scripts/enable_spi0_overlay.sh       # SPI0 使能（已真机落地）
```

## 8. 工程规约摘要（改代码前必读 `AGENTS.md` 原文）

- **隐私红线**：论文/答辩/评审类文档只存本地 `H:\毕设论文\`，绝不写入仓库或上传 GitHub；仓库只留代码、配置、测试与技术文档。
- **README 双语强制同步**：功能/结构/结果变化必须同步更新 `README.md` 与 `README.en.md`。
- **真实数据**：所有实验数据、图表、日志必须来自真实运行；未验证的结论明确标注（仓库里"31 条全程 SAFE 不称零误报""增强后 DANGER 高于基线"等表述就是这个文化的体现）。
- **测试必跑**：改算法/逻辑后 `pytest tests/ -q` 与 `make test` 全绿才能提交。
- **提交规范**：commit message 英文，`type(scope): 简述`（feat/fix/docs/chore/perf）。
- **冲突处理**：与用户既有决策冲突时先确认再执行，不自行推翻（如"谱特征接入评分（w4=0.1）"已是裁决结论，消融 C/D 量化其贡献）。
