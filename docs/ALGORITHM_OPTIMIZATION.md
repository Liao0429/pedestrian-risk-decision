# 算法效率与准确度优化分析

> 针对毕设 4 大算法模块：检测、几何映射、图论拓扑、时序决策。
> 目标平台：Luckfox RV1106（单核 1.2GHz，256MB，1TOPS NPU）。

## 一、当前算法的改善效果

| 模块 | 算法 | 改善点 | 代价/注意 |
|---|---|---|---|
| 感知 | YOLOv5n + INT8 量化 | 推理速度快（NPU 定点化），内存小 | 精度略降（INT8），可接受 |
| 几何 | IPM 逆透视映射 | 像素→地面米坐标，消除"近大远小"，距离/密度计算更准 | 依赖 H 标定准确性 |
| 拓扑 | 邻接矩阵 + 图拉普拉斯 L=D-A | 比单纯人数/密度多刻画"聚集结构"（代数连通度、Fiedler 值） | 特征值计算 O(n³)，n 小时可忽略 |
| 时序 | Kalman 滤波 + FSM | 轨迹平滑、漏检补全、状态滞回防抖，**显著提升时序稳定性** | 需调参（过程噪声/观测噪声） |

**结论：能改善。** 尤其是 **Kalman+FSM 对时序准确度和稳定性提升最大**；**IPM 真机标定**对几何准确度是决定性因素；**INT8** 对速度提升最大。

## 二、更好的算法建议（按性价比排序）

### 1. 时序跟踪：升级到 ByteTrack（强烈推荐，P0）
- 现状：Kalman 单目标平滑（我们自己实现的简单版）
- **更好：ByteTrack**（2022，ECCV，开源自带 C++）
  - 原理：Kalman 预测 + IoU 关联 + **低分框二次关联**，能更好地处理遮挡和 ID 切换
  - 提升：多人跟踪鲁棒性、漏检补全、轨迹连续，比单纯 Kalman 强很多
  - 边缘端：C++ 实现，计算量小，RV1106 可跑
- 实现：把 `KalmanTracker` 换成 ByteTrack 的多目标关联逻辑，接口不变

### 2. 拓扑分析：补充 DBSCAN 聚类（推荐，P1）
- 现状：图拉普拉斯谱特征刻画"聚集结构"
- **更好/更直观：DBSCAN 聚类**（基于密度聚类，O(n log n)）
  - 直接输出"人群簇"：簇数、每簇人数、簇中心、最大簇占比
  - 与"拥挤度/局部聚集"语义天然吻合，答辩更好讲
- 建议：谱特征（图拉普拉斯）保留作理论深度，**加 DBSCAN 作为工程化决策特征**（更快更直观）

### 3. 几何：IPM 真机标定（P0，准确性关键）
- 现状：H 是手填假设（720x480 梯形）
- **更好：真机标定**——在画面中放标定板/已知尺寸矩形，用 `cv::findHomography` 或张正友标定法求 H，存成文件加载
- 提升：地面坐标误差从"假设"降到"厘米级"，直接提升建边和密度准确度

### 4. 检测模型：可试 YOLOv8n（P2，可选）
- 现状：YOLOv5n（成熟、快）
- **更好：YOLOv8n**（精度略高、训练工具链更好）；YOLOv10n 也可
- 但 RV1106 上 YOLOv5n/YOLOv8n 量化后帧率接近；**优先保持 YOLOv5n**，若精度不足再换
- 更轻：YOLO-Fastest / NanoDet（精度更低，一般不必要）

### 5. 决策 FSM：加 EMA 时序平滑（P1）
- 现状：FSM 滞回防抖
- **更好：对输入特征做指数滑动平均（EMA）**，再进 FSM，进一步平滑噪声；或加滑动窗口投票
- 复杂度极低，效果直观

## 三、不建议在 RV1106 上用的"更好算法"
- 深度估计（Monodepth 等）：太重，RV1106 跑不动
- Transformer 检测器（RT-DETR/DINO）：算力不够，延迟高
- 大规模重识别（ReID 网络）：内存/算力超限
- 图神经网络（GNN）：对 n 个小图收益有限，且边缘端部署复杂

## 四、总结建议（优先级）
1. **P0：ByteTrack 多目标跟踪**（替代简单 Kalman，鲁棒性大提升）
2. **P0：IPM 真机标定**（几何准确度根基）
3. **P1：DBSCAN 人群聚类**（补充/替代拉普拉斯谱，更直观高效）
4. **P1：决策特征 EMA 平滑**（时序更稳）
5. **P2：YOLOv8n 可选**（检测精度余量）

当前正在实现的基础版（图拉普拉斯 + Kalman + FSM）已能改善效果；后续按上述优先级升级，效率和准确度还能再上一个台阶。
