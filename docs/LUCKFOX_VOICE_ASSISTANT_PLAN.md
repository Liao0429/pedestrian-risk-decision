# Luckfox 单板语音对话大模型方案（网络 + 本地双套）

> 仿照小智 AI 思路，但**不引入 ESP32**，直接在 Luckfox Pico Max 单板上实现"语音对话大模型"，并与现有行人感知/风险决策系统联动。
> 要求：**网络方案 + 本地方案双套**，演示时网络断也能兜底。

## 一、总体思路

Luckfox 已有：YOLO 行人检测 + 复杂网络风险决策 + RTSP（C++）。
新增：语音采集 → ASR(语音转文字) → LLM(理解/回答/工具调用) → TTS(文字转语音) → 播放。

与检测系统联动：语音助手可通过本地接口查询检测结果（人数、等级），并控制舵机/告警。

## 二、硬件需求（单板，性价比优先）

| 器件 | 型号建议 | 参考价 | 说明 |
|---|---|---|---|
| 麦克风 | USB 麦克风（免驱） | ¥15~30 | 即插即用，Ubuntu 识别为 USB Audio |
| 声卡/喇叭 | USB 声卡 + 3W 喇叭 或 直接 USB 音箱 | ¥15~40 | USB 音频输出，免驱 |
| （可选）I2S 麦克风 | INMP441 | ¥10 | 需要驱动，较麻烦，不优先 |

> 推荐用 **USB 麦克风 + USB 音箱**，Linux 免驱，最省事。

## 三、网络方案（演示主用，效果好）

```
USB麦克风 → 录音(WAV) → 云端 ASR → 文本
 → 云端 LLM(智谱/DeepSeek) → 回答文本
 → 云端 TTS(edge-tts/智谱TTS) → 音频 → USB喇叭
```

| 环节 | 方案 | 说明 |
|---|---|---|
| ASR | 讯飞/百度/OpenAI Whisper API | 中文识别准 |
| LLM | 智谱 GLM / DeepSeek（已有 key） | 能力强，可工具调用 |
| TTS | edge-tts（微软免费）或智谱 TTS | 音质自然 |

优点：效果好、中文准、能力强。缺点：需联网、按量计费（演示成本极低）。

## 四、本地方案（离线兜底，防断网）

```
USB麦克风 → 本地 ASR(Vosk/sherpa-onnx 小模型) → 文本
 → 本地 LLM(Needle 2) 或 规则引擎 → 回答文本
 → 本地 TTS(espeak-ng/pico2wave) → USB喇叭
```

| 环节 | 方案 | 内存/体积 | 说明 |
|---|---|---|---|
| ASR | **Vosk 中文小模型**（约 50MB）或 sherpa-onnx 极小模型 | ~30-80MB | 离线识别固定命令/短句 |
| LLM | **Needle 2**（14MB，28MB 内存，linux-armv7 官方支持） | ~30MB | 结构化输出/工具调用；也可用预设规则应答 |
| TTS | **espeak-ng**（极小）或 pico2wave | <10MB | 音质机械，但离线可用 |

优点：完全离线、无成本、无延迟。缺点：识别/回答能力有限（适合固定问答，如"现在多少人"）。

> 内存预算：Luckfox 256MB。检测程序 ~13MB + Vosk ~50-80MB + Needle2 ~30MB + TTS ~10MB + 系统 ~100MB，**总体约 200MB 以内，可运行但偏紧**。若内存紧张，本地 ASR 可换更小的模型或改用"关键词唤醒 + 预设意图"。

## 五、与检测系统联动

语音助手（Python 进程）与 C++ 检测进程通过**本地 Unix socket / HTTP(127.0.0.1:端口)** 通信：

- 用户问"现在多少人？" → ASR → LLM 工具调用 `query_risk` → 读检测结果 → 组织回答 → TTS
- 用户说"报警" → 工具 `enable_alarm(true)`
- 检测到 DANGER → C++ 主动发消息给语音助手 → 播报"检测到人群聚集，DANGER 等级"

## 六、演示兜底策略（防止出错）

| 场景 | 兜底 |
|---|---|
| 断网 | 自动切本地方案（Vosk + 规则/Needle2 + espeak-ng） |
| 麦克风没声 | 提供文本输入调试口（`--text "现在多少人"` 直接走 LLM 回答） |
| 本地 ASR 识别差 | 预设固定命令词表，模糊匹配即可触发 |
| TTS 无声 | 屏幕同时显示回答文字，保证演示不冷场 |

## 七、实施路线（分阶段）

- 阶段 1：USB 麦克风/音箱在 Luckfox 上出声音（arecord/aplay 测试）
- 阶段 2：网络方案（Python 脚本：录音→ASR→LLM→TTS 全链路）
- 阶段 3：本地方案（装 Vosk 小模型 + espeak-ng；接 Needle 2）
- 阶段 4：与检测系统联动（socket 通信 + 工具调用）
- 阶段 5：演示切换脚本（一键切网络/本地）

## 八、结论

- **可行**：Luckfox 单板即可做语音对话大模型，无需 ESP32
- **双套方案**：网络(好) + 本地(稳)，演示双保险
- 与现有视觉检测融合，形成"看得见+听得懂+会说话"的完整成品
- 与"小智 ESP32"方案比，单板更简洁；小智方案可作为后续扩展提及
