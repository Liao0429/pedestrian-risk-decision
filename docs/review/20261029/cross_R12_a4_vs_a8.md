## 质疑点 ①：BOM v2 的 VBUS=Pin20（L91）与 go2rtc 8080（L191）定为 P0 是否过严？

**判断：VBUS=Pin20 定 P0 合理但表述误导；go2rtc=8080 定 P0 过严，应为 P1。**

### 1.1 VBUS=Pin20 —— 事实正确，P0 合理，但"照做必翻车"因果链不成立

- 事实核对：BOM v2 L91 `VBUS_5V | J1(+5V) → U1 排母 VBUS 脚（Pin20）→ U2 输入`；`design.json` 实测 **U1-40=5V、U1-38=GND**，v1.5 Gerber 电源网络完全正确；`docs/hardware/touchscreen.md` L94 确认 Pin20=UART3_RX。agent8 引用无误。
- 支持 P0 的理由：BOM v2 是唯一一本"从零照做"的 PCB 手册（§3.1~3.5 明确引导在嘉立创 EDA 新建工程、按 §3.3 网络表连线），若有人按它的网络表重新画板/改板，5V 会直通 GPIO1_D1，存在电气损坏风险。作为**构建手册的正确性问题**，P0 成立（与本人 A4 报告一致）。
- 质疑点：agent8 的表述"照 BOM 连线/改板会把 5V 接到 UART3_RX""答辩执行手册硬错误，照做必翻车"，把**条件风险**说成了**必然风险**。实际答辩链路中，硬件实物走的是 v1.5 Gerber + `嘉立创下单说明.md`（引脚全部正确），BOM v2 的 Pin20 只影响"按 BOM 从零重做"这一分支。答辩当日影响是**间接的**（若操作者不看下单说明而只看 BOM v2 才可能踩坑）。更准确表述应为：**P0（构建路径正确性）/ 答辩当日影响 P1（间接、可绕过）**。
- 附带事实：BOM v2 自身还留了 Type-C 母座（J2）供电的可选路径，即使 Pin20 接错，开发板也可经 USB-C 独立供电，进一步降低"翻车"必然性。

### 1.2 go2rtc=8080 —— 事实正确，但 P0 明显过严

- 事实核对：BOM v2 L191 `:8080`；`scripts/start_demo.sh` L60/L79、`scripts/setup_go2rtc_demo_stream.sh` L29/L94、`docs/WEB_VIEWER.md` 全部为 **1984**。agent8 引用无误。
- 质疑点：这是**单一 URL 笔误**，恢复成本约 5 秒——`start_demo.sh` 启动成功后会直接打印 `http://$IP:1984`，操作者照屏幕输出即可；且 BOM v2 自己的"防翻车"表声明**核心展示不依赖网络**（触摸屏+LED+语音本地自包含），网页观看只是增强项。按 agent8 自己的 P0 定义"照做必翻车"衡量，**打不开一个非核心网页 ≠ 翻车**。合理定级：**P1**（真实错误、需修正，但答辩现场影响轻微且可即时恢复）。
- 同类对比：agent8 把 8080 与 VBUS 并列为"两处 P0 硬错误"，严重度不匹配——一个是可能烧板/断电的电气错误，一个是 URL 拼写错误。

**建议**：BOM v2 L91 保留 P0 级修正优先级，但报告措辞改为"按 BOM 从零构建时会接错（有损坏风险）；现有 v1.5 Gerber 正确，答辩实物不受影响"；L191 降为 P1，并指出 start_demo.sh 会自动打印正确地址这一现成缓解。

## 质疑点 ②："已完成 PCB v1.5 Gerber"与 v1.0 串口屏方案并存——"三版并存"描述是否准确？收敛建议是否可行？

**判断：并存事实准确，但"三版"描述不完整；agent8 的收敛建议在文档层面可行，但解决不了位号级接口冲突，收敛不彻底。**

### 2.1 实际并存的不止三版，而是四个状态 + 一个内部版本号混乱

实测核对：

1. **v1.0 规格书**：`docs/hardware/PCB_BOARD_DESIGN.md`，串口屏+DFPlayer 完整网络表（J5=DFPlayer、J6=串口屏、J7=喇叭、J8=告警开关、SW1=总开关、U2 可选）。agent8 引用正确。
2. **v1.5 Gerber（实际可打样包）**：`G:/毕设论文/02_答辩准备/PCB_Gerber/`，`design.json` 确认 U1-40=5V/U1-38=GND，J11=SPI 触摸屏 8P，J6 仍是串口屏 4P、J8 仍是告警开关 2P。**电源正确、DRC 已过、可直接打样。**
3. **BOM v2 手册**：描述的是**一块从未生成的 v2 板**——位号表与 v1.5 Gerber 大面积冲突（见质疑点 ④）。
4. **generate_pcb.py 的 `V2=True` 模式**：v2 信号直连走线已写好但从未运行，design.json/Gerber 仍为 V2=False 产物。

此外，**Gerber 包自身版本命名混乱**：`嘉立创下单说明.md` 标题写"v1 电源底板版"，正文又出现"J11（v1.1 新增）"和"v1.5 已把 5V/GND 直连"，生成日期写 2026-10-27 而 Gerber 文件时间戳为 10-28 01:15。**连"已完成"的实物文件包自己都没说清自己是 v1 还是 v1.5。**

agent8 把问题概括为"v1.0 文档 + v1.5 Gerber + BOM v2 三版并存"，方向正确，但漏掉了第 4 个状态（V2=True 未生成）和 Gerber 包内部版本号自相矛盾这两层。

### 2.2 收敛建议可行性评估

agent8 建议：① PCB_BOARD_DESIGN.md 更新为 v1.5 或标注历史存档；② 同步导读 L196；③ README L187 加注释。

- **文档层面可行**，但"把 PCB_BOARD_DESIGN.md 更新为 v1.5"不如"顶部标注 v1.0 历史存档 + 指向 `嘉立创下单说明.md`"干净——v1.5 的全部正确信息已完整存在于下单说明中，重写一份规格书只会制造第三份可能不一致的文档。
- **关键缺口**：收敛不只是版本号同步。BOM v2 的位号表（J6=SPI 屏、J8=USB-A、J9~J11=LED、J12~J15=按键、U2=MP1584）与 v1.5 Gerber 实物位号（J6=串口屏、J8=告警开关、J11=SPI 屏、无 LED/按键/MP1584）冲突，**不改位号表，光改版本号，答辩组装时照样对不上号**。必须二选一：
  - 方案 A（推荐，成本低）：**冻结 v1.5 Gerber 为答辩实物**，重写 BOM v2 §3.2/§3.3/§3.7 的位号与组装步骤，使其与 v1.5 丝印一致（J6=串口屏预留、J11=SPI 屏、J8=告警开关、LED/按键走开发板直插或扩展板）；同时把 `generate_pcb.py` 的 V2=True 标注为"未生成、未验证"。
  - 方案 B（成本高）：运行 `generate_pcb.py`（V2=True）生成并 DRC/3D 验证 v2 Gerber，让 BOM v2 描述的就是真实打样件。
- 另需顺手修正：下单说明.md 的版本命名统一为 v1.5，生成日期改为实际时间；H:/G: 盘符问题（A8 P2-2 已提）在下单说明 L3 同样存在，它是打样入口文档，应一并改。

**结论：agent8 的"三版并存"属实但只是冰山一角；其收敛建议可行但不充分——真正的收敛必须以"v1.5 Gerber 位号为唯一事实源"重写 BOM v2 位号/组装章节，或反向生成并验证 v2 Gerber。**

## 质疑点 ③：内存口径统一为"9~13MB 区间 + 典型值"是否合理？

**判断：方向正确，但 agent8 自己给出的"稳态典型 10.5~11MB"仍犯它批评的同一毛病（偏向早期采样点），建议口径需要再修正。**

### 3.1 原始数据核对（long_stability.jsonl 10 点 RSS）

| 点序 | 时间 | RSS |
|---|---|---|
| 1 | 10-27 04:13 | 11176 KB = 10.91 MB |
| 2 | 04:20 | 10800 = 10.55 |
| 3 | 04:22 | 10800 = 10.55 |
| 4 | 04:36 | 10800 = 10.55 |
| 5 | 05:05 | 10920 = 10.66 |
| 6 | 06:17 | 10396 = 10.15 |
| 7 | 06:57 | 9656 = 9.43 |
| 8 | 08:23 | 9340 = 9.12 |
| 9 | 12:24 | 9320 = 9.10 |
| 10 | 10-28 08:28（重启后） | 13440 = 13.12 |

- 全区间 **9.10~13.12 MB**，"9~13MB"作为全区间表述正确。
- **中位数 10.55 MB**，均值约 10.4 MB。
- **稳态（无重启）9 个点分布在 9.10~10.91 MB**，其中 4 个点（7~12.5h）在 9.10~10.15 MB。

### 3.2 对 agent8 建议的质疑

- agent8 说"README 只取了前 5 个好看的点"——**属实**（README L116 的 10.5~10.9MB 恰好对应前 5 点）。
- 但 agent8 建议的统一口径"**稳态典型 10.5~11MB**"**同样只覆盖前 5 个点**：稳态 9 点中，后 4 点（9.10~10.15MB）落在该区间之外。若采纳此口径，答辩时评委若追问"为何后 4 个采样点是 9.1~10.2MB"，会陷入与现在相同的"口径对不上数据"的窘境。
- 另外 A8 的 10 点列表只列了 9 个数（漏了一个 10.55 重复点），虽不影响区间结论，但作为"全量重算"报告是个小瑕疵。

**建议统一口径改为**：`RSS 常态 9~11MB（28h 长稳 10 点，中位约 10.5MB）；全区间含重启瞬时峰值 9~13MB；12.5MB 为早期版本快照`。这样区间、典型值、异常值、历史值全部有原始数据支撑，且不再有任何"取哪一段"的选择性嫌疑。

## 质疑点 ④：agent8 是否遗漏了更严重的 PCB 相关文档错误？

**判断：遗漏严重。agent8 声称"P0 级矛盾集中在 BOM v2 的两处硬错误"，但 BOM v2 至少还有 3 处同等级硬错误未被其 P0 清单收录，其中两处比 go2rtc 端口严重得多。**

### 4.1 【遗漏 P0】BOM v2 L95/L96 舵机 PWM 引脚整体错位

- BOM v2 L95：`PWM_PAN = 开发板 Pin5（PWM8_M1）`；L96：`PWM_TILT = 开发板 Pin4（PWM9_M1）`。
- 实测（官方引脚图 + 实机 pinmux，见 agent4_pcb.md §一/§二）：**Pin5 = PWM10_M1、Pin4 = PWM11_IR_M1；PWM8_M1 = Pin7、PWM9_M1 = Pin6**。
- 影响：照 BOM v2 接线，两个舵机接在错误 PWM 通道上，**云台完全不动**——这是答辩演示"云台跟踪行人"核心环节的致命错误，严重度不亚于 VBUS 引脚。agent1 报告 Q-3 提过"两套引脚互斥"但未给出正确引脚；agent8 作为以 BOM v2 为主要审查对象的报告，P0 清单居然完全没有 PWM 引脚这一项，属于**选择性收录**。

### 4.2 【遗漏 P0】BOM v2 L99 语音 UART4 引用幻影设备 `/dev/ttyS4`

- BOM v2 L99：`语音 UART | 开发板 UART4（/dev/ttyS4）→ J5 TX/RX`。
- 实机验证（agent4_pcb.md §二-b）：**当前固件没有 `/dev/ttyS4`**（只有 `/dev/ttyFIQ0` 调试串口）；且 UART4_TX/RX 位于 **Pin6/Pin7，与 PWM9/PWM8 完全同脚**——即使重新编译固件使能 UART4，也会与舵机 PWM 物理冲突。
- 影响：BOM v2 把 DFPlayer 作为"语音兜底方案"（L38、L211），但**该兜底路径在现有硬件上根本不存在**。更值得警惕的是 `docs/hardware/voice_module.md` L91 也写着"UART4 默认固件已使能（设备节点 /dev/ttyS4）"——**仓库文档与实机不符**，而 agent8 还引用了这份文档作为 Pin40 的证据（引用本身正确，但未发现其 UART4 断言错误）。
- 补救：语音兜底应改为 GPIO 蜂鸣或直接删除 DFPlayer 兜底描述；voice_module.md 的 ttyS4 断言需标注"待固件使能/与 PWM 冲突"。

### 4.3 【遗漏 P1→P0 边界】BOM v2 位号表与 v1.5 Gerber 接口定义大面积冲突

逐焊盘核对 `design.json` 与 BOM v2 §3.2 位号表：

| 位号 | v1.5 Gerber 实物（design.json） | BOM v2 §3.2 定义 | 冲突 |
|---|---|---|---|
| J6 | 串口屏 4P（SCREEN_TX/RX） | 触摸屏排针（SPI+触摸） | **完全不同接口** |
| J7 | 喇叭 2P（SPK_P/SPK_N） | 喇叭 2P 端子 | 一致 |
| J8 | 告警开关 2P（SW_ALARM） | **USB-A 母座**（麦克风/扩展） | **完全不同接口** |
| J9~J11 | 仅 J11=SPI 屏 8P，无 J9/J10 LED | J9~J11=LED 3P 排针 | 冲突 |
| J12~J15 | 不存在 | 按键 2P ×4 | 不存在 |
| U2 | 不存在（无 MP1584 焊盘） | MP1584 降压模块（5V→3.3V） | 不存在 |
| SW1 | 存在（VIN→5V 串联） | BOM v2 位号表未列 | BOM 遗漏 |

- 最危险的是 BOM v2 L126 组装步骤"USB 麦克风插 J8（或开发板 USB）"——在 v1.5 实板上，J8 是 2P 告警开关，**照做会把 USB 插到开关上**。
- agent8 的 P1-1 只提到"BOM v2 引用旧文档自相矛盾"这一层，没有逐位号核对 BOM v2 与 v1.5 Gerber 的接口差异。这恰恰是"答辩执行手册"与"实际打样件"之间最直接的矛盾。

### 4.4 【连带】BOM v2 L88 "照 PCB_BOARD_DESIGN.md 连线"是双重错误引用

- BOM v2 L88 声称 §3.3 网络表"照 PCB_BOARD_DESIGN.md 连线"，但 v1.0 文档根本没有 Pin20/VBUS/SPI 屏网络（它通过 USB-C J2 给开发板供电，屏幕走 UART3 串口屏）——**BOM v2 引用的文档既不支持它自己的网络表，也不是当前版本。**agent8 P1-1 提过此点但未展开为独立问题。

### 4.5 小瑕疵（不影响结论）

- agent8 P0-1 称"已完成的 PCB v1.5 Gerber"，但工作日志 L51 原文是"**v1.5 可打样**"，Gerber 文件确已完成（DRC 已过），但**无证据表明已实际下单打样**。措辞宜为"已完成 Gerber（可打样）"，避免被误读为"板子已到手"。

## 最高价值质疑（Top 5，供主审决策）

1. **agent8 的"P0 级矛盾集中在两处"结论不成立**：BOM v2 至少还有 **PWM 引脚整体错位（L95/96，舵机必不动）**与 **UART4=/dev/ttyS4 幻影设备（L99，DFPlayer 兜底不可行）+ voice_module.md 同款错误断言**两个同等级硬错误，且前者的答辩现场影响（核心云台演示失效）远大于 go2rtc 端口。BOM v2 应按 A4 报告的修正映射表（PWM_PAN=Pin7、PWM_TILT=Pin6、VBUS=Pin40）一次性重写 §3.2/§3.3。
2. **P0 定级过严/过松并存**：VBUS=Pin20 定 P0 合理但答辩当日影响是间接的（v1.5 Gerber 正确）；go2rtc 8080 定 P0 明显过严（应为 P1，脚本会自动打印正确地址、网页非核心链路）。
3. **"三版并存"实为"四状态 + 包内版本号混乱"**：除 v1.0 文档 / v1.5 Gerber / BOM v2 外，还有 generate_pcb.py `V2=True` 未生成的 v2 状态，且下单说明.md 自身 v1/v1.1/v1.5 混用。收敛必须**以 v1.5 Gerber 位号为唯一事实源重写 BOM v2 位号与组装章节**（或反向生成验证 v2 Gerber），仅同步版本号不解决问题。
4. **BOM v2 位号表与 v1.5 Gerber 逐焊盘冲突**：J6（SPI 屏 vs 串口屏）、J8（USB-A vs 告警开关）、J9~J15/U2 在实板上不存在，组装步骤 L126"USB 麦克风插 J8"会把 USB 插到告警开关上——这是比版本号漂移更危险的执行级错误，agent8 未逐位号核对。
5. **内存统一口径建议需再修正**："9~13MB 区间 + 典型值"方向对，但"稳态典型 10.5~11MB"仍只覆盖前 5 个采样点；应改为"常态 9~11MB（中位约 10.5MB）+ 重启瞬时峰值 13.1MB + 12.5MB 早期快照"，四份文档照此同步，才能彻底堵住"口径对不上数据"的追问。
