## 0. 结论摘要（TL;DR）

论文存在一个**致命逻辑断裂**：全文将"图拉普拉斯谱特征（Fiedler 值等）"包装为增强决策的核心创新（README 特性、架构图、SYSTEM_PRINCIPLE 2.3.1），但**谱特征在所有运行路径中都未进入风险决策**——C++ 板端（enhanced_decision.cc）与 Python 实验（crowd_test_enhanced.py、ablation_study.py）的 FSM 输入只有 `n / density / r_gcc / trend`，Fiedler/谱半径/代数连通度/特征熵仅"透出"用于打印与画面叠加。消融实验中"谱特征"开关是**死代码**，C 组与 B 组在全部 6 个视频上结果逐位相同。该问题同时摧毁了"创新点"、"谱特征收益"与"消融实验"三个章节的可信度。

其余高严重度问题：**以稳定性（切换次数）代替准确性（风险判断正确率）**、**以检测指标（检出率 82.5%）代替风险决策指标**、**阈值标定仅 30 张图且三类样本评分区间严重重叠**、**实验用 YOLOv8n 而部署用 YOLOv5n-INT8**、**111 条视频无风险真值**。以下逐条展开。

## 1. 研究问题是否清晰？"创新点"是否只是常规技术集成？

**严重度：高。**

**问题**：题目是"行人感知与风险决策"，但 README 与实验把 70% 篇幅给"感知"（YOLO 检出率、IPM、图特征），风险决策部分没有独立于检测的评价指标。研究问题可被概括为"在 1TOPS 边缘设备上做人群聚集风险分级"，但全文没有定义"风险"的 ground truth，没有与任何既有方法（人群计数、密度估计、传统聚集检测、其他分级器）对比，因此无法回答"相比已有方案，本系统在什么问题上、好多少"。

**证据**：
- README「🧪 实验结果」两节标题分别是"图片基线（500 张）"与"视频增强"，指标是检出率、等级分布、切换次数——**没有一项是风险判断准确率**。
- docs/algorithms.md「Kalman 核心验收指标」用的是**合成匀速轨迹**（RMSE 0.147m），测试对象是滤波器，不是风险决策。
- 全部"创新点"均为成熟技术的拼装：YOLOv5n（现成）、IPM（经典几何变换）、邻接矩阵+拉普拉斯谱（教科书图论）、DBSCAN（1996）、Kalman（1960）、FSM 滞回（控制理论常识）。文档自称的"复合算法流水线"属于**常规系统集成**，不构成研究贡献，除非能证明组合后产生了新的可验证能力。

**反例**：SYSTEM_PRINCIPLE 2.3.1 声称核心创新是"区分'人数多但分散'与'人数相同但局部聚集'"。但该能力由 `density / r_gcc` 两个经典图特征即可实现，与"谱"无关；而论文真正的卖点词"谱特征"又没有进决策（见第 2 节）。即：能工作的部分不新，新的部分不工作。

**修正建议**：
1. 把研究问题收敛为可检验的形式，例如："在低算力边缘端，能否用轻量检测+空间图特征实现与静态规则相当/更优的人群聚集风险分级？"并给出风险 GT 定义（见第 5、6 节）。
2. 增加一个非增强基线（如纯密度阈值法、DBSCAN 最大簇占比法）做公平对比，量化"图特征"带来的 AROC/准确率提升。
3. 若坚持谱特征为创新点，必须把它真正接入决策并证明收益（见第 2 节），否则从论文中删除"谱特征提升决策"的表述。

## 2. 复杂网络方法是否有可测量收益？——关键逻辑错误：谱特征未进 FSM 决策

**严重度：致命（Critical）。**

**问题**：README 宣称"谱特征提升风险语义准确性"（README 特性栏："复杂网络拓扑：邻接矩阵 + 图拉普拉斯谱分析（Fiedler 值/谱半径/代数连通度）"；README 消融节："谱特征作为图连通性指标参与计算与显示"），架构图把 EnhancedDecision 标为"Kalman 平滑 + 谱特征 + FSM 时序"。但代码中谱特征只被计算、打印、显示，**从未参与风险等级判定**。

**证据（逐路径）**：
1. **C++ 板端**：`src/luckfox_rtsp_yolov5/src/enhanced_decision.cc:147-169` 中 `graph_.computeFeatures()` 算出了 `fiedler/spectral_radius/algebraic_connectivity/eig_entropy`，但 `processFrame` 第 162-169 行构造 `FsmFeatures f` 时只填 `n/density/r_gcc/clustering` 与 `trend`；谱特征仅写入 `EnhancedResult` 结构体（`enhanced_decision.h:99-103`），在 main.cc 中只用于 `printf` 打印（main.cc:361-363）。**FSM 决策输入不含任何谱特征。**
2. **Python 实验**：`scripts/crowd_test_enhanced.py:107-113` 把谱特征放进 `feat` 字典，但 `fsm.update({"n": n, "density": density, "r_gcc": r_gcc}, now_ms)`（第 120 行）根本不读它们；`feat` 仅用于画面文字（第 63-64 行 fiedler 显示）。
3. **消融脚本**：`scripts/ablation_study.py:62-68` 在 `use_spectral` 时计算谱特征并 `feat.update(...)`，但 `feat` 之后从未被使用（第 69-71 行 fsm.update 传入的是新字典）。**C 组的谱特征开关是死代码。**
4. **FSM 本身**：`src/algorithms/risk_fsm.py:202-216` 评分公式只读 `n/density/r_gcc/trend`，`clustering` 在文档中明确标注"预留，当前不参与评分"（第 184 行）。

**反例（消融数据直接证明谱特征零贡献）**：`results/rerun/_ablation.json` 中，**B 组（+Kalman）与 C 组（+Kalman+谱特征）在全部 6 个视频上的 `switches` 与 `dist` 逐位相同**（mixkit_134: 16/16；mixkit_13192: 4/4；mixkit_3428: 0/0；mixkit_4519: 0/0；mixkit_4178: 45/45；mixkit_50134: 5/5）。这不是"谱特征收益小"，而是谱特征在消融中物理上不可能产生任何影响。

**修正建议**：
1. **二选一**：① 把谱特征真正接入决策——例如用归一化拉普拉斯第二小特征值 μ₂（值域 [0,2]，跨帧可比，见 agent3 报告）作为 FSM 第 4 个特征并重跑消融；② 若坚持当前架构，则**必须**删除"谱特征提升风险语义准确性/增强决策"的表述，改为"谱特征作为可视化辅助指标输出"，并把创新点改写为"图连通特征（density/r_gcc）+ Kalman + FSM 的时序稳定分级"。
2. 修复 `ablation_study.py`：要么让 `use_spectral` 真正影响输出（接入 FSM），要么把 C 组从消融中删除，否则消融实验名不副实。
3. 若保留 fiedler 输出，需先解决 agent3 指出的三个技术缺陷：Fiedler 值随 n 缩放跨帧不可比（P5=0.382 vs P30=0.011）、图不连通时 λ₂≡0 与"完全分散"不可区分、Jacobi 在 max_sweeps=100 内对 n≥10 长链不收敛时静默回退 0（`graph_laplacian.h:163-175,300-305`，`converged` 标志证实存在该回退路径）。

## 3. 风险决策规则阈值（n / rho / gcc）的理论与实验依据

**严重度：高。**

**问题**：规则阈值（danger: n≥10 且 (rho≥0.55 或 gcc≥0.80)；warning: n≥5 且 (rho≥0.28 或 gcc≥0.55)）在 ARCHITECTURE 与 risk_engine.cc 中只声明"可配置"，无任何理论推导、场景分析或敏感性实验。FSM 阈值（up_warning=0.40 / up_danger=0.65 等）的标定依据（docs/algorithms.md 9.2）与真实数据不符，且样本量极小、类别不可分。

**证据**：
1. **标定样本极小**：docs/algorithms.md 9.2 声称阈值依据 `results/baseline/results.json` 标定；该文件实际只有 **30 张图（SAFE 23 / WARNING 5 / DANGER 2）**，且权重为 yolov8n.pt。用 2 个 DANGER 样本定"危险阈值"无统计意义。
2. **文档数据与实测不符**：文档称"DANGER 样本评分约 0.67~0.68，WARNING 样本约 0.62~0.66"。实测（按评分公式 0.4·norm(n)+0.3·rho+0.3·gcc 复算）：
   - DANGER：0.675~0.679（基本吻合）；
   - WARNING：**0.515~0.660**（文档下限 0.62 错误，最低 0.515 的样本是 000000480133_14）；
   - SAFE：0.000~**0.660**。
3. **类别评分不可分**：标定集中一个 **SAFE 样本（000000254814_13：仅 3 人，rho=1.0, gcc=1.0）评分 0.660**，高于 `up_danger=0.65`！这意味着按当前 FSM，3 人紧挨（<2m）就会从 SAFE 升级 WARNING 再升级 DANGER，与"13 人 DANGER 样本（0.675）"仅差 0.015。安全等级边界完全不可分。
4. **SAFE 被误升级率高**：30 张标定图中 **4/23 的 SAFE 样本评分 ≥ up_warning=0.40**（000000254814_13=0.660、000000553396_14=0.506、000000061507_14=0.460、000000168883_4=0.405），即按 FSM 阈值，标定集中约 17% 的 SAFE 图会被判 WARNING。
5. **规则阈值无依据**：为什么 n=10、rho=0.55、gcc=0.80？为什么 FSM 权重 w1=0.4/w2=0.3/w3=0.3？文档没有任何出处（文献、场景假设、或敏感性分析）。`norm(n)=min(n/20,1)` 还导致**≥20 人的分散人群评分天然 ≥0.4 必为 WARNING**（0.4·1 + 0.3·低密度 + 0.3·低gcc ≈ 0.41~0.50），与 SYSTEM_PRINCIPLE"分散不危险"的叙事在 n≥20 时自相矛盾。

**反例**：构造 20 人完全分散（两两距离 >2m）场景：n=20, density=0, r_gcc=0.05 → score=0.4+0+0.015=0.415 ≥ 0.40 → WARNING。即"人数多但分散"在 FSM 下仍报警，核心卖点失效。

**修正建议**：
1. 用**带风险标注的数据**（哪怕是自建规则标注：如按真实距离/密度/滞留时间定义三档）重新标定，并给出标定集规模、类别分布、混淆矩阵与阈值-误报率曲线（ROC/PR）。
2. 对 n/rho/gcc/权重做敏感性分析（网格扫描），展示阈值在 ±20% 内变化时等级分布与切换次数的稳定性。
3. 修正 docs/algorithms.md 9.2 的 WARNING 分数区间描述（0.515~0.660），并公开标定代码与数据。
4. 将 `n_ref` 与权重的物理含义讲清楚，或改用可解释规则（如最大簇人数 ≥ 阈值 且 簇内平均间距 ≤ 阈值）。

## 4. 消融实验能否区分各模块贡献？

**严重度：高。**

**问题**：不能。`ablation_study.py` 的 4 组配置设计存在三个缺陷：
1. **谱特征组是死开关**（见第 2 节）：C 组与 B 组在代码层面完全相同，6 个视频结果逐位相同，消融无法给出谱特征贡献。
2. **无法分离 FSM 与谱特征**：D 组（完整）相对 C 组只增加了 FSM，因此 D−C 的差异被全部归因给 FSM，但"谱特征+FSM 联合"的贡献无法拆开；也没有"仅 FSM、无谱特征"的组合，无法检验谱特征是否与 FSM 有交互。
3. **样本量小且被挑选**：只有 6 条视频（mixkit_134/13192/3428/4519/4178/50134），README 却把该 6 视频的平均值（35.2→11.7→4.0）与 111 条全量的平均值（4.00）混在同一章节陈述，两个"平均"来自不同总体，读者无法区分。

**证据**：
- `scripts/ablation_study.py:25-30` 组合定义：B=(Kalman, 无谱, 无FSM)，C=(Kalman, 有谱, 无FSM)；但 C 的谱特征只写进 `feat` 字典（第 62-68 行），`feat` 未参与任何输出（fsm.update 用的是新 dict，第 70 行）。
- `results/rerun/_ablation.json`：B 与 C 的 `switches`/`dist` 在全部 6 视频完全相等（见第 2 节）。
- README「消融实验」：`Kalman 跟踪平滑使平均切换次数下降约 67%（35.2 → 11.7），FSM 时序决策进一步稳定（→ 4.0）`——6 视频均值（35.17→11.67→4.00）与 `_comparison_summary.json` 的 111 视频均值（base 46.37→enh 4.00）混用，且 README 上一行"平均每条等级切换 4.00 次"指的是 111 条，容易让读者误以为 35.2→4.0 是全量结果。

**反例**：若把消融图 `fig_ablation.png` 的 C 组柱状图与 B 组叠加，两者完全重合——答辩时只需问"请指出谱特征在消融中的独立贡献曲线"，作者无法回答。

**修正建议**：
1. 重新设计消融：至少 5 组——A 基线（逐帧规则）、B +Kalman、C +FSM（无谱）、D +Kalman+FSM、E 完整（+谱特征接入决策后）。这样才能分别归因 Kalman、FSM、谱特征。
2. 若谱特征不接入决策，删掉谱特征组，明确"本文消融仅评估 Kalman 与 FSM 的稳定性贡献"。
3. 统一统计口径：要么全 111 条做消融，要么明确标注"6 条代表性视频"，不要把两个总体的平均数混写。
4. 补充指标：除切换次数外，报告等级分布变化、误报/漏报率（需 GT）、以及各组件对最终等级的净改变帧数。

## 5. 是否用稳定性（切换次数下降）代替准确性（风险判断正确率）？

**严重度：高。**

**问题**：是。全文核心指标是"等级切换次数下降"（5147→444，即 46.37→4.00 次/视频），但没有任何风险真值（GT）证明"更少的切换 = 判断更准"。切换次数下降可以来自三种非准确性原因：
1. **状态保持与确认帧人为锁存**：FSM 升级需连续 3 帧、DANGER 进入后至少保持 10 帧/1000ms（risk_fsm.py:249-266）。这必然降低切换次数，但也会**延迟告警**并**压制短时危险事件**。
2. **阈值整体右移/评分语义改变**：增强前后 DANGER 帧从 21969 降到 7807（-64%），触发 DANGER 的视频从 102 条降到 40 条（-61%）。这本质是把报警策略调保守了，可能是"更准"，也可能是**大规模漏报**——没有 GT 无法判断。
3. **Kalman 平滑漏检外推**：Kalman 在漏检时外推位置（kalman_filter.h），把"人消失"变成"人还在原地"，会人为维持聚集特征，从而减少切换。

**证据**：
- `results/rerun/_comparison_summary.json`：base_sw=5147 → enh_sw=444；base_lv DANGER=21969 → enh_lv DANGER=7807；base_danger（出现 DANGER 的视频数）=102 → enh_danger=40；base_safe=9 → enh_safe=31。
- 反例（增强反而"更不稳定"的视频被隐藏）：`_ablation.json` 中 mixkit_3428 与 mixkit_4519 的 D 组切换次数（2）比 B/C 组（0）**更高**，且 mixkit_4519 从基线 0 次切换（603 帧全 DANGER）变为 2 次切换并出现 81 帧 WARNING/2 帧 SAFE。若这些视频是持续危险场景，这就是增强引入的漏报。
- `risk_fsm.py:257-266`：DANGER 降级被 hold 强行阻止（frame+ms 双条件），这是切换次数下降的直接来源之一，与判断准确性无关。

**修正建议**：
1. **必须建立风险 GT**。可行方案：对 111 条视频做帧级人工标注三档风险（或至少视频级标注），或使用合成场景（已知人数/间距/聚集程度）生成 GT，然后报告混淆矩阵、精确率/召回率、F1、以及"报警延迟帧数"。
2. 把"切换次数"降级为次要指标（稳定性/用户体验），不能作为正确性证据。
3. 报告增强前后 DANGER 帧减少的**具体原因分解**：多少来自 FSM 锁存、多少来自 Kalman 外推、多少来自阈值语义变化。
4. 补充最坏情况延迟：从"危险聚集出现"到"系统输出 DANGER"的最短/平均帧数（当前架构至少 3+3 确认帧 + 10 帧保持，在 10Hz 下约 1.6s 才能稳定进入 DANGER，若帧率更低则更慢）。

## 6. 是否用检测效果代替风险判断效果？

**严重度：高。**

**问题**：是。README 图片基线的主指标是"检出率 82.5%/高密度 79.4%"，这是**目标检测的召回率**，不是风险分级准确率。风险分级从未被独立评估：
- 图片 500 张只有等级分布（SAFE 414/WARNING 61/DANGER 25），没有"该图真实风险等级"的标注，无法验证分级对错。
- 视频 111 条只报告切换次数与等级分布，没有任何真值。
- "31 条未触发风险报警（含少量低照度场景检测器漏检，已用亮度+检测人数双重核对）"——这个"核对"没有输出任何可复现的核对记录（如每条的亮度值、检测人数、人工判定），属**无依据数据**。

**证据**：
- `results/rerun/images500_baseline/results.json`：500 张图的结果只有 `level/n/m/density/r_gcc/clustering/detections`，无 GT 风险标签；`gt` 人数仅编码在文件名后缀（如 `_14`），且 README 的 82.5%/79.4% 与该文件一致（gt_total=3089、det=2548；14+ 人群仅 **12 张图**、gt=175、det=139）——**高密度检出率 79.4% 只基于 12 张图、175 个行人**，作为论文主指标统计功效极弱。
- README「31 条未触发风险报警」的"已用亮度+检测人数双重核对"无对应结果文件。
- 系统输出的是 SAFE/WARNING/DANGER，但全文没有任何一个数字回答"分级判断对了百分之几"。

**反例**：一张 10 人分散的图（真实安全）与一张 10 人紧挨的图（真实危险），若检测都完整，两者 `n` 相同；只有 rho/gcc 不同。论文没有证明 rho/gcc 阈值能正确区分这两类——因为根本没有 GT。

**修正建议**：
1. 为 500 张图片补充风险 GT（可按人数×聚集程度定义三档，或人工标注），报告分级混淆矩阵与准确率。
2. 高密度指标要么扩充样本，要么标注"基于 12 张图，仅作参考"。
3. 把"检出率"明确标注为检测模块的召回率，与风险决策指标分节呈现。
4. 为 111 条视频提供可复现的核对脚本/结果（亮度统计、检测人数曲线、人工标注 csv）。

## 8. 答辩评委最可能否定设计的 Top 10（每条给证据与应对）

1. **"谱特征到底进了决策没有？"（致命）**
   证据：`enhanced_decision.cc:162-169` FSM 输入无谱特征；`ablation_study.py:62-71` 谱特征为死代码；`_ablation.json` B==C。
   应对：要么把归一化谱特征（μ₂）真正接入 FSM 并给出收益数据，要么公开承认谱特征仅为可视化指标，删去"增强决策含谱特征"的表述，将创新点改为"图连通特征 + 时序 FSM 的稳定性贡献"。

2. **"切换次数下降凭什么说明判断更准？"**
   证据：`_comparison_summary.json` DANGER 帧 -64%、报警视频 102→40；无风险 GT；FSM 确认帧+保持机制必然降低切换。
   应对：补充帧级/视频级风险 GT 的混淆矩阵与 F1；把切换次数降为次要稳定性指标。

3. **"你的消融实验 B 和 C 为什么完全一样？"**
   证据：`_ablation.json` 6 视频 B==C（switches 与 dist 均相同）。
   应对：修复消融脚本（谱特征接入决策或删除 C 组），重跑并更新图表与 README。

4. **"风险阈值怎么定的？为什么 3 个人也会判 DANGER 而 13 个人才 0.675？"**
   证据：`results/baseline/results.json` 标定仅 30 图/2 DANGER；SAFE 样本（3 人，rho=1, gcc=1）评分 0.660 > up_danger=0.65；4/23 SAFE 样本评分 ≥0.40。
   应对：扩充标定集、公开标定脚本与混淆矩阵、做阈值敏感性分析；修正 algorithms.md 9.2 的错误区间。

5. **"实验用的是 YOLOv8n，板端是 YOLOv5n-INT8，凭什么说板端有 82.5% 检出率？"**
   证据：`crowd_test.py:417` 默认 `yolov8n.pt`；`ablation_study.py:84` 同样；README 部署章节写 YOLOv5n。
   应对：在板端重跑至少一个代表性视频/图片子集，给出板端实测检出率与等级分布；或在论文中明确标注"PC 实验为算法验证，板端性能需另行评估"。

6. **"111 条视频没有标注，你的 31 条不报警是正确还是漏报？"**
   证据：README"31 条未触发风险报警"；`_comparison_summary.json` base_danger=102→enh_danger=40。
   应对：提供视频级人工标注（危险/安全/不确定）与核对记录；至少给出每条的检测人数与亮度曲线作为佐证。

7. **"你的'复杂网络'创新在哪里？Fiedler 值和代数连通度不是一个数吗？"**
   证据：`graph_laplacian.h:36-37` 两字段等价；系统无复杂网络特性分析。
   应对：精简术语，删除重复字段；如果谱不是卖点，就围绕 density/r_gcc/DBSCAN 的工程贡献重新定位。

8. **"检测漏掉 18% 的人（高密度漏 20.6%），你的图是残缺的，风险判断还成立吗？"**
   证据：`images500_baseline` 总体召回 82.5%、14+ 人群 79.4%（仅 12 图）。
   应对：做"漏检敏感性分析"（随机删除 10%/20% 节点，观察等级翻转比例）；或在论文中讨论漏检对图连通性的影响及置信度下限。

9. **"系统从危险出现到报警要多少帧？会不会短时聚集根本没报？"**
   证据：`risk_fsm.py` 升级需 3+3 确认帧 + DANGER 保持 10 帧/1000ms；无延迟指标。
   应对：补充端到端告警延迟统计（最短/平均/最坏），与帧率、确认帧参数的关系表。

10. **"消融平均 35.2→4.0 是 6 条视频还是 111 条？为什么两个数字混在一起？"**
    证据：README 消融节（6 视频均值）与视频增强节（111 视频均值）并列。
    应对：统一口径，分别标注样本量；建议直接对 111 条全量跑消融（脚本支持）。
