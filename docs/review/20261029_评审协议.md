## 一、目标

1. **代码**：全面审查 C++/Python 代码，修复缺陷，优化性能，补齐**中文注释**。
2. **PCB**：核对 PCB 扩展底板设计（`docs/hardware/PCB_BOARD_DESIGN.md` + `G:/毕设论文/02_答辩准备/答辩硬件展示方案_v2_BOM与PCB手册.md`）与实际硬件选型/引脚定义是否一致，修正错误。
3. **3D 外壳**：评估并设计合理的 3D 打印外壳（尺寸/开孔/安装/装配），输出 STL + 真实渲染效果图 + 中文标注装配图。
4. **效果展现**：PCB 预览图、外壳渲染图、装配图等可展示素材。
5. **交叉讨论**：不低于 50 轮次多 Agent 交叉讨论、鉴定、评价、优化，全程记录台账。

## 三、轮次规则

- **1 轮 = 1 个 Agent 的一次独立执行**（独立评审 / 交叉质疑 / 修复 / 验证 / 裁决撰写）。
- 每轮输出写入 `docs/review/20261029/roundNN_*.md` 或对应报告文件，并在 `ROUND_LOG.md` 登记。
- 流程：R1~R8 独立评审 → R9~R16 交叉质疑 → R17 裁决 → R18~R35 修复实施 → R36~R45 复验与第二轮评审 → R46~R50+ 最终鉴定与答辩问题。
- 严重度：P0（必须修）/ P1（优先改进）/ P2（可选）。

## 四、纪律

- 评审 Agent **只读不修改**代码；修复 Agent 只动自己负责的文件。
- 所有实验数据必须真实，未验证项标注「未验证」，不编造。
- 涉及核心算法/阈值/数据的改动先建实验方案，跑测试验证。
- 每次改动后同步更新 README/工作日志（用户硬性要求）。
- 报告文件不上传 GitHub 远程；最终合并前由用户决定是否清理。
