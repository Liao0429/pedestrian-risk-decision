## 二、交叉质疑（真实分歧与共识）

### 共识（多 Agent 独立指向同一问题）
1. **谱特征未进入风险决策**（Agent1/3/6 独立确认）——消融 C 组与 B 组逐帧相同是铁证。Agent4 用 `_ablation.json` 数值复核 6 条视频验证。
2. **111 视频无 GT，准确率/误报率不可声称**（Agent4/6）——"零误报"无真值校验。
3. **IPM 未真机标定**（Agent2/4/6/8）——地面米制坐标缺乏物理可信度。
4. **实验模型(YOLOv8)与部署模型(YOLOv5n INT8)不一致**（Agent1/4/6）。
5. **无 CI / 消融脚本失真**（Agent4/7 一致）。

### 争议与交叉评价
- **争议 A：谱特征要不要接入 FSM？**
  - Agent3 提议：归一化拉普拉斯（λ₂∈[0,2]）或相对代数连通度，成本与 Jacobi 相同，可使 Fiedler 跨规模可比 → 接入 FSM 评分。
  - Agent1 提议：先删"谱特征提升准确性"结论；若接入需实验证明收益。
  - Agent5/嵌入式视角：Jacobi O(n³) 每帧在 RV1106 是开销，接入前需评估算力成本（当前已每帧计算，接入零增量成本）。
  - **裁决**：**先做消融一致性修复 + 文档收敛（删无据表述）；谱特征接入 FSM 作为 P1 实验性改进**，用消融 C vs B 是否产生差异作为验收标准。若实验证明无收益则保持"仅显示用"并在论文如实表述。
- **争议 B：优化帧率应先换模型还是先改流水线？**
  - Agent2：证据（-O2 无效，仍 6FPS）指向单线程串行是瓶颈，不换模型。
  - Agent5/嵌入式：应先做主循环耗时打点（VI/RKNN/编码各段时间），再决定检测降频/线程解耦。
  - **裁决**：采纳——先打点，再降频/解耦；不引入新模型（成本高、答辩风险大）。
- **争议 C：人工 GT 标注是否值得投入？**
  - Agent4：低成本标注（图片 2h + 视频抽帧 12-18h）可支撑混淆矩阵/召回/漏报。
  - Agent6：没有 GT 就没有准确率类指标，论文必须收敛表述。
  - **裁决**：答辩前优先做**图片 500 张风险等级标注**（约 2h）作为实验章节的 GT 基线；视频全量标注若时间不足，至少抽 10-20 条代表性视频标注。

### 需要实验/数据裁决的假设（不得声称已验证）
- 归一化拉普拉斯是否改善风险语义 → 需消融对比（C vs B 差异）验证。
- 检测降频/线程解耦对帧率与稳定性的影响 → 需真机打点后实施并测帧率。
- C++/Python 平滑语义对齐后对指标的影响 → 需回归测试 + 真机对比。
